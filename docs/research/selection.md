# 選択をブラウザに持たせられるか

dom 経路の本文は実 DOM のテキストなので、塞いでいるものを外せば OS の選択が使えるはず、
という仮説を iOS 26.4 (シミュレータ) で試した。

塞いでいるのは 4 か所。

```
backend/dom/backend.ts   userSelect: "none" / WebkitUserSelect: "none"
input/pointer.ts         mousedown / touchend / pointerdown の preventDefault
```

## focus が無ければ、ネイティブ選択は完全に動く

指の処理を丸ごと止めて外すと、

- **OS の編集メニューが出る** (コピー / 選択部分を検索 / 調べる / …)
- **つまみが縦書きでも正しく出る**。掴んで列に沿って伸ばせる
- **塗りは櫛にならない**。列幅いっぱいの帯が、列をまたいで綺麗に繋がる

つまり **「縦書きのネイティブ選択は見た目が壊れる」は、少なくとも iOS 26.4 では成り立たない。**
自前で描いている理由のうち、見た目の話は根拠を失っている。

## focus が隠し入力にあると、選択が始まらない

指の処理は止めたまま、ページから `focus()` を呼ぶだけにして同じ長押しをすると、**何も起きない**。
キーボードは出ているのに、選択もつまみもメニューも出ない。
長押しの認識自体は (focus が無いときに動いたので) されている。

**focus 以外は上と同じ条件**なので、原因は focus の有無で確定。

## 結論

**「IME のために隠し入力へ focus を置く」と「本文のネイティブ選択」は同時に成立しない。**
選択を OS に渡すなら、focus の持ち方から作り直すことになる。
