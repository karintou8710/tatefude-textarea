# contenteditable の縦書き

[0001](../decisions/0001-縦書きテキストエリアのアーキテクチャ.md) で捨てた選択肢。
**実装しようとしたときに「削除が画面に反映されない」バグを踏んでいる** (当時の iOS / Safari)。

## iOS 26.4 (シミュレータ) で測り直した

`writing-mode: vertical-rl` を当てた `contenteditable` で、

- 文字を挿入 … 反映される
- **5 文字目を `execCommand("delete")` で削除 … 反映された** (`len=9`、表示も一致)

**当時のバグは再現しなかった。** 直っているのか、条件が違うのかは分からない。

ただし WebKit のソースには **「レイアウト後の再描画が vertical-rl で壊れている」** という FIXME が残っている
([b/70762](https://bugs.webkit.org/show_bug.cgi?id=70762) → [webkit-bugs.md](webkit-bugs.md))。当時踏んだのはこれかもしれない。

- 折り返しをまたぐ削除、IME 変換中の削除、複数ノードにまたがる削除

## 分かっていること

再現しなくても [0001](../decisions/0001-縦書きテキストエリアのアーキテクチャ.md) の判断は変わらない。
`contenteditable` を使わない理由は**レイアウトを握れないこと**でもあるため。
