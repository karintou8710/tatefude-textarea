# 目指すもの

**主要ブラウザ (モバイルを含む) で編集の挙動が揃う縦書きテキストエリア。**

## 存在理由は Safari

Blink (Chrome / Edge) だけで足りる案件は、素の `<textarea>` を使えばいい。
わざわざライブラリを入れるのは、**Safari が対象に入っている**とき。Mac も iOS も壊れている。
測った範囲は [research/textarea.md](research/textarea.md) と [research/ios.md](research/ios.md)。

売りは「全環境で動く」ことではなく、**編集の挙動をエンジンに依らず同じにする**こと。

## 揃うもの / 揃わないもの

| | |
| --- | --- |
| 揃う | キー割り当て、指のジェスチャ、キャレットの置き方、選択の伸ばし方、選択とキャレットの描画、コンテナが変わったときの追従 |
| 揃わない | **折り返し位置・行送り・字の向き**。組版はブラウザに任せているので、エンジン差がそのまま出る |

組版まで揃えるなら自前でレイアウトする (canvas) しかないが、a11y とページ内検索を失う
→ [decisions/0004](decisions/0004-バックエンドを-2-つ持つ.md)

## 目指さないもの

- **Safari 専用**。それでは PC 用にもう 1 つ入力系を持つことになり、誰も選ばない
- **エンジンごとに実装を切り替える**（Blink ではネイティブに委譲する等）。唯一の売りである編集の挙動の同一性を失う
- **`contenteditable`**。そもそも Safari で壊れている → [decisions/0001](decisions/0001-縦書きテキストエリアのアーキテクチャ.md)
