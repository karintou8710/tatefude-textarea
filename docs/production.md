# 実務で使われるための課題

MIT で公開する。売り物にするという話ではなく、**誰かの製品に入っても困らない水準**にする、という意味。

## 必須

- **a11y**。いまは壊れている。支援技術から見えるのは「テキストを持った div」と「値が空の 1x1 textarea」
  → [limits.md](limits.md)。ここが通らないと「Blink なら素の textarea のほうが上」で終わる
- **API を固めて出す**。まだ `0.0.0` で npm に無い。出した時点で互換性の責任が生まれるので、
  公開する範囲 (いまは dom だけ)・semver・破壊的変更の予告の仕方を先に決める
- **対応範囲を宣言する**。どのエンジンのどのバージョンまで保証するのか。入れる側は必ず気にする
- **フォーム連携**。`name` での送信、`required`、`label` との結び付き。いまは何も無い

## 測っていない (測れば分かる)

- **長文**。数万字でレイアウトにどれだけかかるか。コンテナが変わるたびに全行を測り直す作りなので、
  ここは先に測ったほうがいい
- **SSR**。React ラッパを Next.js などで使ったときに落ちないか
- **Android の IME**。各社キーボードでの変換・確定

## 直せるが未着手

- **Firefox**。`setPointerCapture` が合成イベントの id を拒否する
- **回帰を検出する手段**。iOS まわりは CI で 1 つも落ちない → [testing.md](testing.md)
- 指まわりの積み残し (ルーペ、キャレットだけのときのメニュー、選択のドラッグ&ドロップ)

## 原理的に返せない要求

OS の編集メニュー、「調べる」「翻訳」、スペースキー長押しのトラックパッド化、アプリ間のドラッグ&ドロップ
→ [limits.md](limits.md)。**先に言っておく**類のもの。
