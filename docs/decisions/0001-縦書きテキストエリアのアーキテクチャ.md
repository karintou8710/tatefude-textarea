# 0001. 縦書きテキストエリアのアーキテクチャ

## 決めたこと

**入力は隠し入力で受け、レイアウトはブラウザ (`writing-mode`) に任せ、選択とキャレットは自前で描く。**

## 背景

Safari は Mac も iOS も、縦書きの `<textarea>` と `contenteditable` が壊れている。
`<textarea>` は矢印の移動が効かず、キャレットも列幅の 1/3 ほどの短い線で描かれる
→ [../research/textarea.md](../research/textarea.md)。
直るのを待つにも、こちらから直しにいくにも時間がかかる。

## なぜ

壊れている部分だけを自前に置き換える、いちばん小さい構成だから。
**レイアウト (行分割・禁則・字の向き) はブラウザが正しくやる**ので、そこは任せる。

## 代償

OS の編集メニュー・選択 UI・a11y を失った。入力まわりの面倒を全部こちらで持つことになった
→ [../limits.md](../limits.md)

## 比較対象

| | 捨てた理由 |
| --- | --- |
| 素の `<textarea>` | Blink なら足りるが、Safari で壊れている。それが出発点 |
| `contenteditable` | ブラウザが DOM を書き換えるのでレイアウトを握れない。加えて、**削除が画面に反映されないバグを踏んだ** (当時の Safari。iOS 26.4 では再現せず → [../research/contenteditable.md](../research/contenteditable.md)) |
| canvas に全部描く | レイアウトの結果までエンジンで揃うが、a11y とページ内検索を失う → [0004](0004-バックエンドを-2-つ持つ.md) |
| EditContext | 隠し入力が要らなくなる本命。**WebKit に無い**ので、いまは選べない |
