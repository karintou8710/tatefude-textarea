# 0006. ハンドルは dom 経路だけに持たせる

## 決めたこと

選択の両端のハンドルは dom 経路だけが描く。canvas は `hitHandle()` が `null` を返すだけ。

## 背景

[0005](0005-指の割り当ては-iOS-の編集可能テキストに合わせる.md) で指の作法を揃えたが、
指が要るのは iOS で、そこで動かすのは dom 経路だけ。
一方 [0004](0004-バックエンドを-2-つ持つ.md) には「両バックエンドは同じ振る舞いをする」という約束がある。

## なぜ

canvas にも実装できるが、2 倍のコストに見合わない。
product として出すのは dom だけなので、指まわりは dom に寄せる。

## 代償

**「両バックエンドは同じ振る舞いをする」を意図的に降ろした。**
これ以降、指まわりの機能は dom だけに入る。canvas をどう位置づけるかは 0004 の宿題。

## 比較対象

| | 捨てた理由 |
| --- | --- |
| 両方に入れる | コストが 2 倍。canvas を指で触る人がいない |
| どちらにも入れず OS に任せる | ネイティブ選択が使えない → [0007](0007-選択も自前で描く.md) |
| キャレットだけのときにも丸を出す | Android の作法。iOS は出さないし、タップした場所に丸が乗ると続けてタップできない |
