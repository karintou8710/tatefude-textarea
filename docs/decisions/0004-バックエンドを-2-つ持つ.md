# 0004. バックエンドを 2 つ持つ

## 決めたこと

`dom` (writing-mode にレイアウトさせる) と `canvas` (字を 1 つずつ置く) の 2 実装を持つ。
**公開するのは dom だけ**。canvas は `index.ts` に出していない。

## 背景

[0001](0001-縦書きテキストエリアのアーキテクチャ.md) でレイアウトをブラウザに任せたが、
そうすると**折り返し位置も行送りも字の向きもエンジンごとに違う**。
「編集の挙動は揃うが、レイアウトの結果は揃わない」という線引きになる → [../goals.md](../goals.md)

## なぜ

レイアウトの結果まで揃えたいなら、自分でレイアウトするしかない。その道が canvas。
行分割・禁則・字の向きは canvas を触らないので、node のテストで回せるのも大きい。

## 代償

機能を足すたびにコストが 2 倍かかる。
「両バックエンドは同じ振る舞いをする」という約束は、指のつまみを dom だけに入れた時点で
**既に一度崩している** → [0006](0006-つまみは-dom-経路だけに持たせる.md)

## 比較対象

| | 捨てた理由 |
| --- | --- |
| dom だけ | レイアウトの結果を揃える道が消える。フォントさえ同じなら canvas は揃えられる |
| canvas だけ | a11y もページ内検索も失う。禁則と字の向き (UAX #50) を永久に自分で保守する |
