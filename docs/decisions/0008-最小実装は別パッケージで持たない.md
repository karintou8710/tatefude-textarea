# 0008. 最小実装は別パッケージで持たない

## 決めたこと

引き算で確かめるための最小実装 (`packages/core-minimum`) を、パッケージとして置かない。
**引き算で分かったことだけをこの文書に残す。**

## 背景

`core` が何を足してきたのかを引き算の側から見るために、縦書き・隠し入力・自前のキャレットだけを
残した最小実装を別パッケージで書いた (`src` 7 ファイル + テスト)。
読み比べの役は果たしたが、置き続けると **2 つ目の実装を保守する約束**になる。
`core` を直すたびに「minimum でも同じ判断をするか」を決めることになり、CI も 2 本走っていた。

## なぜ

引き算の価値は**分かったこと**にあって、動く実装そのものにはなかった。
分かったことを文書にすれば、追従の義務なしで同じ判断ができる。

## 引き算で分かったこと

### これが無いと、このライブラリを使う理由が無くなるもの

- **縦書き**。行分割と折り返しは `writing-mode` に任せる
- **隠し入力**でキー・IME・クリップボードを受ける
- **キャレットと選択を自前で描く**。Safari の `<textarea>` は縦書きで壊れているので、
  ここを任せると挙動が揃わない → [0003](0003-キャレットを自前で描く.md), [0007](0007-選択も自前で描く.md)

### 捨てられるもの

| 捨てるもの | 影響 |
| --- | --- |
| canvas バックエンド | dom 1 つに決め打つと、バックエンドの抽象ごと要らなくなる → [0004](0004-バックエンドを-2-つ持つ.md) |
| 履歴 (undo / redo) | 無くても書ける |
| 指のジェスチャ | ハンドル・長押し・連続タップの判定が消える。クリックしてキャレットを置くだけになる |
| キャレットの点滅 | 出しっぱなしでよい |
| スクロールの戻し (`anchorCaret`) | キーボードでコンテナが縮むときの追従。iOS 専用の込み入った話 |
| **矢印キーでの移動** | 波及が一番大きい (下記) |
| `placeholder` / `maxLength` / `readOnly` / `disabled` | 後から足せる |
| react ラッパ | core を直接使う |

### 矢印を捨てると何が消えるか

**一番効く引き算**。`core` の複雑さのかなりの部分がここから来ている。

- **キャレットが数値 1 つになる**。`preferEnd` (折り返しの境目でどちらの行に着けるか) が要らない
- **`goal` が消える**。行を跨ぐときに「元いたインライン方向の位置」を持ち歩く必要がない
- **レイアウトに聞くことが減る**。`moveAcross` / `lineEdge` / `linesPerPage` が全部不要になり、
  残るのは「クリックした場所が何文字目か」と描くための矩形だけ
- **② が ④ を知らなくなる**。`core` では「↓ を押したら何文字目か」が本文だけでは決まらず、
  編集操作がレイアウトに問い合わせている (`edit/command.ts` → `layout.ts`)。
  矢印が無ければこの依存ごと消える。**逆に言えば、矢印を持つ限りこの依存は消せない**

### 口を作るかどうかは、実装の数で決まる

最小実装は 1 層 1 ファイルにして、口 (インターフェース) を作らなかった。
**差し替える相手が居ないうちは、インターフェースは行数を増やすだけになる。**

`core` でも同じ基準を当てると、`Backend` だけが残る (dom / canvas の 2 実装がある)。
隠し入力と指は実装が 1 つずつしか無いので、口で受けても差し替える相手が居ない。

もう 1 つ、最小実装の `view.ts` が `ResolvedOptions` をそのまま受けずに
自前の `ViewOptions` を持っていたのも同じ話で、**options が増えても、
その部品が読めるものは増えない**ようにするため。

## 代償

- **「本当に引き算できるか」を実装で確かめる手段が消える**。この文書は腐る
- 最小構成から始めたい人に見せる動くコードが無くなる

## 比較対象

| | 捨てた理由 |
| --- | --- |
| 別パッケージで残す | `core` を直すたびに追従の判断が要る。CI も 2 本になる |
| `core` の中にサンプルとして置く | 4 層のどこにも属さない。層の外に足すと辺が増える |
| 消して記録も残さない | 引き算で分かったことは、足すときの判断基準そのもの |
