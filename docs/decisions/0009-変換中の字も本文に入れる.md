# 0009. 変換中の字も本文に入れる

## 決めたこと

IME の変換中の字を `EditState.text` に入れる。`composition` が持つのは範囲だけ。

## 背景

最初は預かる作りだった。`composition.text` に字を持ち、`textOver` で表示用テキストへ
差し込んで描く。本文 (`state.text`) は確定するまで動かない。

理由は「変換中に `onChange` が飛ぶと、react の controlled が値を書き戻して変換が切れる」
——だがこれは**この作りでは起きない**。IME を受けるのは隠し入力で、本文は別に持っている。
`state.text` を書き換えても隠し入力の `value` には触らないので、変換は切れない。
切れるのは contenteditable と素の `<textarea>` の話だった。

## なぜ

**座標系が 2 つになるのをやめたい。**`composition.start` は本文の座標、`rangeOf` が返すのは
表示用テキストの座標。混ぜるとずれるが、型では区別できない。

入れてしまえば `textOver` も `caretOver` も `displayCaret` も要らなくなり、
描く側は本文の座標だけを見る。

## 代償

| | |
| --- | --- |
| 履歴に積む | **タダだった。**`history.push` は 700ms 以内の同種をまとめるので、1 変換が 1 つの undo になる。モードを足す必要は無い |
| `onChange` が飛ぶ | native `<textarea>` も変換中に `input` を飛ばす。読む側は `state.composing` で見分ける |
| `maxLength` が効く | 上限ぎりぎりで変換すると、変換中に切られる。IME の中の文字列とずれるが、頻度は低い |

3 つとも受けると決めた。

## 残るもの

範囲は持つ。下線と文節のために `start` / `end` / `activeStart` / `activeEnd` が要る。

## 比較対象

| | 捨てた理由 |
| --- | --- |
| 預かって表示に混ぜる | 座標系が 2 つ。`textOver` / `caretOver` / `displayCaret` の 3 つが要る |
| 本文に入れて範囲も持たない | 下線を引く場所が分からない |
