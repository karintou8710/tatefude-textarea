# 0007. 選択も自前で描く

## 決めたこと

本文に `user-select: none` を当て、選択の塗りも自前の要素で描く。

## 背景

本文は実 DOM のテキストなので、理屈の上ではブラウザの選択が使えるはずだった。
当初は「縦書きのネイティブ選択は塗りが櫛になる」を理由にしていたが、
iOS 26.4 で測ったら**列幅いっぱいに綺麗に塗れていた**。この理由は失効している。

## なぜ

測り直した結果、残った理由はこれ。

1. **focus が隠し入力にあると、本文のネイティブ選択がそもそも始まらない**
   (実測 → [../research/selection.md](../research/selection.md))。
   IME のために focus を置く以上、OS の選択とは両立しない
2. canvas 経路では原理的に不可能。字が DOM に無い

## 代償

OS の編集メニュー・ハンドル・ルーペ・選択ジェスチャを**全部自分で作ることになった**。
いま作ってあるのは長押し / ダブル・トリプルタップ / ハンドル / 浮かぶメニューまで。ルーペは無い。

## 比較対象

| | 捨てた理由 |
| --- | --- |
| ネイティブ選択を使う | focus と両立しない (実測)。OS メニューもハンドルも綺麗な塗りも手に入るが、IME を諦めることになる |
| 選択したい瞬間だけ focus を外す | blur でキーボードが閉じ、再 focus にはユーザー操作が要る。毎回開き直すことになる |
